# Dataset

## Current state: synthetic placeholder

No real semiconductor inspection dataset was available when this project was built.
`data/synthetic/` was generated by `ml/datasets/generate_synthetic_dataset.py`, which
procedurally draws grayscale images with wafer/die-like structure (dicing grid lines,
rectangular circuit blocks, via/pad dots, occasional scratch-like "defects") and then
applies the same configurable degradation pipeline used for training
(`ml/preprocessing/degradation.py`) to produce paired clean/degraded images.

This is **not** a substitute for real inspection imagery — it exists so every other
component (analyzer, loader, training, evaluation, API, dashboard) can be exercised
against real files and real computed metrics instead of mocks.

Regenerate or resize it:
```bash
python ml/datasets/generate_synthetic_dataset.py --size 128 --train 200 --val 40 --test 40
```

## Expected real-dataset layout

```
<dataset_root>/
    train/clean/*.png      train/degraded/*.png
    val/clean/*.png        val/degraded/*.png
    test/clean/*.png       test/degraded/*.png
```

Same filename in `clean/` and `degraded/` = a pair. If your dataset instead ships as
a flat folder of images with no `clean`/`degraded` split, `ml/datasets/dataset_analyzer.py`
will still analyze it (reported as `layout: "flat"`) and you'll need to generate
degraded counterparts using `ml/preprocessing/degradation.py`'s `apply_degradation()`,
or adjust `ml/datasets/paired_dataset.py` to your actual layout.

To point everything at your real dataset:
1. Copy/mount it somewhere under `data/` (or elsewhere on disk).
2. Set `paths.dataset_root` in `configs/config.yaml`, or set the `DATASET_ROOT`
   environment variable, to that path.
3. Set `dataset.is_synthetic_placeholder: false` in `configs/config.yaml` (this only
   controls the "synthetic placeholder" warning banner shown in the dashboard).
4. Re-run `python ml/datasets/dataset_analyzer.py` and confirm the reported counts/
   dimensions match what you expect — **do not** trust cached numbers from before
   the swap.

## Real, measured statistics (synthetic placeholder, as generated in this repo)

Run `python ml/datasets/dataset_analyzer.py` to regenerate `data/dataset_report.json`.
As generated by default: 60 train / 15 val / 15 test pairs, 128×128, single-channel
(`L` mode) PNG, paired (`is_paired_dataset: true`).

## Degradation types supported (configurable, `configs/config.yaml -> degradation`)

- **Gaussian noise** — additive, sigma sampled from `gaussian_sigma_range`.
- **Poisson noise** — signal-dependent shot noise, approximating photon/electron-
  counting sensors (e.g. SEM detectors).
- **Sensor-like noise** — Gaussian read noise + per-row bias, approximating
  line-scan detector artifacts.
- **Reduced spatial resolution** — downsample by a configurable integer factor
  (`downsample_scales`) then upsample back, simulating a lower-resolution
  acquisition while keeping paired image dimensions equal for direct pixel-wise
  comparison.

No fixed image dimension is assumed anywhere in the pipeline — the analyzer reports
whatever dimensions are actually present, and the model/training code adapts (patch
size is a configurable crop, not a hardcoded requirement).

## Defect labels

The synthetic dataset does not include defect segmentation masks. **If your real
dataset has defect labels, they are not yet integrated** — see
`docs/evaluation.md` for where to wire them in. This is documented per project
requirement #9/#31 rather than silently ignored.
